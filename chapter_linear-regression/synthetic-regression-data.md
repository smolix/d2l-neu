# Synthetic Data
:label:`sec_synthetic-regression-data`


Before we can train a model we need data. Real datasets are what we
ultimately care about, but when a method performs poorly on one, three
explanations compete: the model may be misspecified, the optimization
algorithm or its implementation may be flawed, or the data may be
pathological. On real data these explanations are difficult to tell apart.
*Synthetic data* removes the ambiguity by construction. If we generate the
data ourselves, we know the true weights $\mathbf{w}^*$, the true bias
$b^*$, and the distribution of the noise. A model of the right form then has
a known target, and any systematic failure to recover $\mathbf{w}^*$ and
$b^*$, beyond what the noise explains, points to the algorithm or its
implementation. A synthetic problem with known parameters, generated by a
model of the form that the method fits, is therefore a useful first test of
a new learning method, before we evaluate it on real data.

This section builds such a test for linear regression. We generate examples
from a linear function with the true parameters $\mathbf{w}^* = (2, -3.4)$
and $b^* = 4.2$, add a little Gaussian noise, and package the result as a
`DataModule`, the class for datasets from :numref:`sec_oo-design`. We then
work out how close a correct fit can come to these parameters, which turns
the comparison into a test with a threshold. Finally, we write the data
loader that serves the examples in random minibatches, the form in which
minibatch stochastic gradient descent consumes them. The next section trains
a linear model on this dataset and holds its estimates to the threshold.

## Generating the Data

We draw the features of each example independently from a standard normal
distribution, with mean $0$ and variance $1$, and stack the feature vectors
as the rows of the design matrix $\mathbf{X}$. Two features keep the true
parameters easy to compare; nothing below depends on that choice. Each label
is the value of the true linear function plus noise:

$$\mathbf{y} = \mathbf{X}\mathbf{w}^* + b^* + \boldsymbol{\epsilon}.$$

The bias $b^*$ is added to every entry, and the entries of the noise vector
$\boldsymbol{\epsilon}$ are drawn independently from a normal distribution
with mean $0$ and standard deviation $\sigma = 0.01$. Each label thus lies
close to the plane $\mathbf{w}^{*\top}\mathbf{x} + b^*$, typically within a
few hundredths. This is the model of :numref:`sec_linear_regression`: a
linear function with Gaussian noise, for which minimizing the squared loss
is the same as maximizing the likelihood
(:numref:`subsec_normal_distribution_and_squared_loss`). A linear model
trained with the squared loss is therefore correctly specified for these
data.

We write the generator as the constructor of `SyntheticRegressionData`, a
subclass of `DataModule`, which serves a dataset's training and validation
examples through the methods `train_dataloader` and `val_dataloader`. The
call `save_hyperparameters()` stores every constructor argument as an
attribute: the true parameters `w` and `b`, the noise level `noise`, the
numbers `num_train` and `num_val` of training and validation examples, and
the minibatch size `batch_size`. The constructor draws all
`num_train + num_val` examples at once, by default 1,000 of each. The
validation examples come from the same process but are not used to fit the
model. The loss on them shows how well the model predicts examples it has
not seen, a question we take up in :numref:`sec_generalization_basics`.

:begin_tab:`jax`
JAX has no global random state. The constructor therefore takes a key,
splits it into two, and draws $\mathbf{X}$ and $\boldsymbol{\epsilon}$ from
different keys. The same key always produces the same dataset. Without a
key, the constructor draws one from a new seed, so that each run generates
a new dataset.
:end_tab:

```{.python .input #synthetic-regression-data-generating-the-dataset-1}
%%tab pytorch
class SyntheticRegressionData(d2l.DataModule):  #@save
    """Synthetic data for linear regression."""
    def __init__(self, w, b, noise=0.01, num_train=1000, num_val=1000, 
                 batch_size=32):
        super().__init__()
        self.save_hyperparameters()
        n = num_train + num_val
        self.X = d2l.randn(n, len(w))
        eps = d2l.randn(n, 1) * noise
        self.y = d2l.matmul(self.X, d2l.reshape(w, (-1, 1))) + b + eps
```

## Recovering the Parameters
:label:`subsec_synthetic-regression-data-recovery`

A test needs a threshold. Even a perfect implementation does not recover
$\mathbf{w}^*$ and $b^*$ exactly, because the noise moves the labels and,
with them, the minimizer of the loss. How far the minimizer moves follows
from the normal equations of
:numref:`subsec_linear-regression-analytic-solution`. As there, we append a
column of ones to $\mathbf{X}$ and the bias to the weights, so that
$\mathbf{w}^* = (2, -3.4, 4.2)$ now has three entries and
$\mathbf{y} = \mathbf{X}\mathbf{w}^* + \boldsymbol{\epsilon}$. The
least-squares estimate $\hat{\mathbf{w}}$ on the $n$ training examples
solves the normal equations
$\mathbf{X}^\top\mathbf{X}\hat{\mathbf{w}} = \mathbf{X}^\top\mathbf{y}$.
Substituting the labels gives
$\mathbf{X}^\top\mathbf{X}(\hat{\mathbf{w}} - \mathbf{w}^*) = \mathbf{X}^\top\boldsymbol{\epsilon}$,
and therefore

$$\hat{\mathbf{w}} - \mathbf{w}^* = (\mathbf{X}^\top\mathbf{X})^{-1}\mathbf{X}^\top\boldsymbol{\epsilon}.$$

The *estimation error* $\hat{\mathbf{w}} - \mathbf{w}^*$ is a linear
function of the noise, so without noise least squares would recover the
parameters exactly.

For our data the matrix $\mathbf{X}^\top\mathbf{X}$ is simple. Its entries
are sums over the $n$ examples of products of two columns. On the diagonal
each product is either the square of the constant $1$ or a squared feature
$z^2$, with mean $1$ and variance $E[z^4] - 1 = 3 - 1 = 2$ for a standard
normal $z$. These sums are therefore close to $n$, within about
$\sqrt{2n}$. Off the diagonal the products have mean $0$, because the
features are independent with mean $0$, and variance $1$, so a sum of $n$ of
them has standard deviation only $\sqrt{n}$. For $n = 1{,}000$ the diagonal
entries are $1{,}000$ for the column of ones and about $1{,}000 \pm 45$ for
the features, and the entries off the diagonal are about $0 \pm 32$. With
$\mathbf{X}^\top\mathbf{X} \approx n\mathbf{I}$, the estimation error
becomes an average over the training examples,

$$\hat{\mathbf{w}} - \mathbf{w}^* \approx \frac{1}{n}\mathbf{X}^\top\boldsymbol{\epsilon} = \frac{1}{n}\sum_{i=1}^{n} \epsilon^{(i)}\mathbf{x}^{(i)}.$$

Each coordinate of the estimation error averages $n$ independent terms
$\epsilon^{(i)} x^{(i)}_j$, each with mean $0$ and variance $\sigma^2$,
since the noise is independent of the features and $x_j^2$ has mean $1$.
Such an average has standard deviation $\sigma/\sqrt{n}$, which
:numref:`sec_prob` calls its standard error. With $\sigma = 0.01$ and
$n = 1{,}000$ training examples, every coordinate of $\hat{\mathbf{w}}$,
the bias included, misses its true value by about
$0.01/\sqrt{1000} \approx 3 \times 10^{-4}$.

We check this prediction by solving the least-squares problem on the
training examples with `lstsq`, as in
:numref:`subsec_linear-regression-analytic-solution`.

We print the estimation errors of the two weights and of the bias, and the

```{.python .input #synthetic-regression-data-recovering-the-parameters-2}
e_w = d2l.numpy(w_hat[:2] - data.w)
print(f'error in w: ({e_w[0]:.1e}, {e_w[1]:.1e})')
print(f'error in b: {float(w_hat[2] - data.b):.1e}')
print(f'standard error: {data.noise / n ** 0.5:.1e}')
```

All three estimation errors are at most a few times $10^{-4}$, the size of
the standard error. For least squares, an error above $10^{-3}$, more than
three standard errors, occurs in fewer than one run in a hundred. This gives
the next section its threshold. Minibatch stochastic gradient descent on the
squared loss approaches the same least-squares estimate, but its random
minibatches keep it fluctuating around that estimate by a similar amount
(the noise ball of :numref:`sec_linear_regression`). A correct
implementation, trained until the loss has converged, therefore lands within
about $10^{-3}$ of the true parameters, and essentially always within
$2 \times 10^{-3}$. An error of $0.1$ cannot be blamed on the noise.
It points to a bug or to an optimization that has not converged; once the
loss has converged, to a bug. The threshold depends on the data: it shrinks
with more examples and less noise (exercise
:exref:`ex_synthetic-regression-data-recovery-under-noise`).

## Reading the Data in Minibatches

Minibatch stochastic gradient descent
(:numref:`subsec_linear-regression-minibatch-sgd`) updates the parameters
with the gradient averaged over a minibatch, a small set of examples drawn
at random. Because the minibatch is random, its average gradient is an
unbiased estimate of the gradient of the full loss; minibatches taken in a
fixed order, for instance sorted by label, would bias every step. Training
makes many passes over the data, called epochs. The usual way to draw the
minibatches is to shuffle the training examples at the start of every epoch
and to cut the shuffled sequence into consecutive pieces of `batch_size`
examples. Every example is then used once
per epoch, and the minibatches differ from one epoch to the next. The
validation examples need no shuffling, since we only average the loss over
them. We read them in their stored order, which makes runs easier to compare
when debugging.

We implement this procedure as the method `get_dataloader(train)`, which
`train_dataloader` and `val_dataloader` call with `train=True` and
`train=False`. Since `SyntheticRegressionData` is already defined, we
attach the method with the decorator `add_to_class` of
:numref:`oo-design-utilities`, which adds a function to an existing class as
a method. Because its body contains `yield`, calling the method returns a
generator, an object that runs the body piece by piece as a loop iterates
over it: each `yield` hands the loop one minibatch, a pair of features and
labels.

```{.python .input #synthetic-regression-data-reading-the-dataset-1}
%%tab pytorch
@d2l.add_to_class(SyntheticRegressionData)
def get_dataloader(self, train):
    n = self.num_train
    if train:  # A fresh random order of the training examples
        indices = torch.randperm(n)
    else:      # The validation examples, in a fixed order
        indices = torch.arange(n, n + self.num_val)
    for i in range(0, len(indices), self.batch_size):
        batch_indices = indices[i : i + self.batch_size]
        yield self.X[batch_indices], self.y[batch_indices]
```

```{.python .input #synthetic-regression-data-reading-the-dataset-1}
%%tab tensorflow
@d2l.add_to_class(SyntheticRegressionData)
def get_dataloader(self, train):
    n = self.num_train
    if train:  # A fresh random order of the training examples
        indices = tf.random.shuffle(tf.range(n))
    else:      # The validation examples, in a fixed order
        indices = tf.range(n, n + self.num_val)
    for i in range(0, len(indices), self.batch_size):
        batch_indices = indices[i : i + self.batch_size]
        yield (tf.gather(self.X, batch_indices),
               tf.gather(self.y, batch_indices))
```

With 1,000 training examples and minibatches of 32, an epoch consists of
$\lceil 1000/32 \rceil = 32$ minibatches: 31 full ones and a last one with
the remaining 8 examples. We count the minibatches of one pass over the
training loader, and then try a second pass over the same loader.

```{.python .input #synthetic-regression-data-reading-the-data-in-minibatches-1}
loader = data.train_dataloader()
sizes = [len(y) for X, y in loader]
print(f'{len(sizes)} minibatches, the last of size {sizes[-1]}')
print(f'second pass: {len([y for X, y in loader])} minibatches')
```

The count matches, but the second pass yields nothing. A generator can be
iterated only once; after one pass it is exhausted. This matters for
training. The `Trainer` of :numref:`sec_oo-design` asks the `DataModule`
for its loaders once and then iterates over them in every epoch, so with
our generator it would train for one epoch and then do nothing, without an
error. Our loader has further limits. It cannot report how many minibatches
an epoch has without running through it, it holds all the data in memory,
and it assembles every minibatch in the same Python process that trains the
model.

## Reusing a Loader Across Epochs

A reusable data loader removes the first two limits. It can be iterated in
every epoch, draws a fresh random order on every pass, and reports its
number of minibatches through `len`. The loaders that deep learning
frameworks provide also remove the other two. For data that do not fit in
memory, or that must be decoded and transformed before use, such as large
collections of images, they read examples from disk and prepare the next
minibatches in parallel workers while the model trains on the current one.
Our dataset fits in memory, so we need only the first two properties.

For data that are already in memory as tensors, we add the method
`get_tensorloader` to the base class `DataModule`, so that every such
dataset can use it. It takes a tuple of tensors whose first axis indexes the
examples, keeps the examples selected by `indices`, and returns a loader
that shuffles them if `train` is true. Where the framework provides such a
loader, `get_tensorloader` returns it; otherwise we write a short class of
our own.

:begin_tab:`jax`
`ArrayLoader` keeps the arrays on the host as NumPy arrays and yields each
minibatch as NumPy arrays, which JAX functions accept and move to the
device. When it shuffles, it splits a new key off its own key on every pass
and draws the order from that key, so that every pass has a new order and
no key is used twice. It keeps the last, partial minibatch unless we ask it
to drop it. The compiled training
and validation steps, which we write in :numref:`sec_linear_scratch`, are
compiled once for every new input shape, so the last minibatch costs one
more compilation of each step per run, not one per epoch.
:end_tab:

```{.python .input #synthetic-regression-data-reusable-data-loaders-1}
%%tab jax
class ArrayLoader:  #@save
    """Minibatches of in-memory arrays, reshuffled each pass if shuffle."""
    def __init__(self, arrays, batch_size, shuffle=False, drop_last=False,
                 key=None):
        self.arrays = tuple(np.asarray(a) for a in arrays)  # On the host
        self.batch_size, self.shuffle = batch_size, shuffle
        self.drop_last = drop_last
        if shuffle and key is None:  # A new seed on each run
            key = jax.random.key(random.getrandbits(32))
        self.key = key

    def __len__(self):
        n = len(self.arrays[0])
        if self.drop_last:
            return n // self.batch_size
        return (n + self.batch_size - 1) // self.batch_size

    def __iter__(self):
        n = len(self.arrays[0])
        if self.shuffle:  # A new key, and hence a new order, on every pass
            self.key, key = jax.random.split(self.key)
            order = np.asarray(jax.random.permutation(key, n))
        else:
            order = np.arange(n)
        for i in range(len(self)):
            start = i * self.batch_size
            batch_indices = order[start : start + self.batch_size]
            yield tuple(a[batch_indices] for a in self.arrays)
```

:begin_tab:`pytorch`
`TensorDataset` pairs the tensors example by example, and `DataLoader` draws
minibatches of `batch_size` examples from it, in a new random order on every
pass when `shuffle=True`.
:end_tab:

:begin_tab:`tensorflow`
`tf.data.Dataset.from_tensor_slices` pairs the tensors example by example.
`shuffle` then draws each next example at random from a buffer of
`buffer_size` examples: a buffer that holds all training examples gives a
uniformly random order, drawn anew on every pass, and a buffer of one
example keeps the stored order, as validation needs. `batch` groups
consecutive examples into minibatches.
:end_tab:

:begin_tab:`jax`
`get_tensorloader` wraps the selected arrays in an `ArrayLoader` that
shuffles only for training.
:end_tab:

:begin_tab:`mxnet`
`gluon.data.ArrayDataset` pairs the arrays example by example, and
`gluon.data.DataLoader` draws minibatches of `batch_size` examples from it,
in a new random order on every pass when `shuffle=True`.
:end_tab:

```{.python .input #synthetic-regression-data-concise-implementation-of-the-data-loader-1}
%%tab pytorch
@d2l.add_to_class(d2l.DataModule)  #@save
def get_tensorloader(self, tensors, train, indices=slice(0, None)):
    tensors = tuple(a[indices] for a in tensors)
    dataset = torch.utils.data.TensorDataset(*tensors)
    return torch.utils.data.DataLoader(dataset, self.batch_size,
                                       shuffle=train)
```

holds 8 examples. Unlike the generator, it yields all 32 again on the second
pass, and every pass starts with different examples because the order is
drawn anew. It also reports the number of minibatches without a pass.

```{.python .input #synthetic-regression-data-concise-implementation-of-the-data-loader-4}
len(loader)
```

From now on, every `DataModule` that holds its data as tensors serves them
through `get_tensorloader`.

We now have a dataset whose true parameters we know, the size of the error
that its noise alone causes, about $3 \times 10^{-4}$, and a loader that
serves the training examples in a new random order every epoch. The next
section implements the linear model, the squared loss, and minibatch
stochastic gradient descent, trains them on this dataset, and compares the
estimates with $\mathbf{w}^*$ and $b^*$. Passing this test tells us that the
implementation recovers parameters that it should recover. It does not tell
us how the method behaves when the model does not match the data, which is
the usual case with real data.

## Summary

A poor result on real data cannot tell a bug from a wrong model; a
synthetic dataset can. We generated labels from a linear function with
known parameters $\mathbf{w}^* = (2, -3.4)$ and $b^* = 4.2$ plus Gaussian
noise, for which a linear model with the squared loss is correctly
specified. The noise moves even the exact least-squares estimate away from
the truth, by about the standard error
$\sigma/\sqrt{n} \approx 3 \times 10^{-4}$, so a correct implementation
trained to convergence should land within a threshold of about $10^{-3}$.
`SyntheticRegressionData` packages the generator as a `DataModule`. Its
loader shuffles the training examples at the start of every epoch and cuts
them into minibatches, 32 per epoch with the last holding 8 examples. A
hand-written generator shows the mechanism but can be iterated only once,
so we use a loader that can be iterated in every epoch and reports its
length: the framework's own, or in JAX a short class of our own.

[The problem]{.kicker}

Suppose a model reaches a poor validation loss on real data. Is the model
wrong, the optimization or its code, or the data?

- **Real data:** the true parameters are unknown, and the three
  explanations are hard to tell apart.

points to a bug, or to an optimization that has not converged.

::: {.slide title="I. The Estimation Error Is Linear in the Noise"}
[Recovering the parameters · derivation]{.kicker}

Append a column of ones to $\mathbf{X}$ and $b^*$ to $\mathbf{w}^*$:
$\mathbf{w}^* = (2, -3.4, 4.2)$ and
$\mathbf{y} = \mathbf{X}\mathbf{w}^* + \boldsymbol{\epsilon}$.

Least squares solves
$\mathbf{X}^\top\mathbf{X}\hat{\mathbf{w}} = \mathbf{X}^\top\mathbf{y}$.
Substitute $\mathbf{y}$:
$\mathbf{X}^\top\mathbf{X}(\hat{\mathbf{w}} - \mathbf{w}^*) = \mathbf{X}^\top\boldsymbol{\epsilon}$, so

$$\hat{\mathbf{w}} - \mathbf{w}^* = (\mathbf{X}^\top\mathbf{X})^{-1}\mathbf{X}^\top\boldsymbol{\epsilon}.$$

::: {.d2l-note}
Without noise, least squares recovers $\mathbf{w}^*$ exactly. The noise
moves the minimizer of the loss, and we need to know how far.
:::
:::

::: {.slide title="II. Standard Normal Features Make XᵀX ≈ 1,000 · I"}
[Recovering the parameters · derivation]{.kicker}

Each entry of $\mathbf{X}^\top\mathbf{X}$ sums $n = 1{,}000$ products of
two columns. A sum of $n$ independent terms of variance $v$ has standard
deviation $\sqrt{nv}$:

| entry | each term | the sum |
|---|---|---|
| a feature squared, $x_j^2$ | mean 1, variance 2 | $1{,}000 \pm 45$ |
| the constant column squared | exactly 1 | $1{,}000$ |
| off the diagonal, $x_j x_k$ or $x_j \cdot 1$ | mean 0, variance 1 | $0 \pm 32$ |

So $(\mathbf{X}^\top\mathbf{X})^{-1} \approx \mathbf{I}/n$, and

$$\hat{\mathbf{w}} - \mathbf{w}^* \approx \frac{1}{n}\mathbf{X}^\top\boldsymbol{\epsilon} = \frac{1}{n}\sum_{i=1}^{n} \epsilon^{(i)}\mathbf{x}^{(i)}.$$
:::

::: {.slide title="III. Each Coordinate Misses by About σ/√n = 3 × 10⁻⁴"}
[Recovering the parameters · derivation]{.kicker}

Coordinate $j$ of the error averages $n$ independent terms
$\epsilon^{(i)} x_j^{(i)}$, each with mean 0 and variance
$\sigma^2 E[x_j^2] = \sigma^2$. An average of $n$ such terms has standard
deviation $\sigma/\sqrt{n}$, its **standard error**:

::: {.d2l-note .rule}
$$\sigma/\sqrt{n} = 0.01/\sqrt{1000} \approx 3 \times 10^{-4}$$
for each weight and for the bias.
:::

Ten times more noise, ten times the error; a hundred times more examples, a tenth of it.

[Assumes: noise independent of the features, $\mathbf{X}^\top\mathbf{X} \approx n\mathbf{I}$.]{.dgm-cap}
:::

::: {.slide title="A Random Minibatch Points the Right Way; a Sorted One Need Not"}
[Reading the data]{.kicker}

At $\mathbf{w} = \mathbf{0}$, $b = 0$ a minibatch's gradient for the bias is
$\partial L / \partial b = -(\text{mean label})$. The labels have mean 4.2
and standard deviation $\sqrt{2^2 + 3.4^2} \approx 3.9$.

| minibatch of 32 | mean label | $\partial L / \partial b$ | step on $b$ |
|---|---|---|---|
| drawn at random | $4.2 \pm 0.7$ | $\approx -4.2$ | up, toward 4.2 |
| the 32 smallest labels | $\approx -4.6$ | $\approx +4.6$ | down, away from 4.2 |

::: {.d2l-note}
A random minibatch's gradient is an unbiased estimate of the full
gradient. Minibatches in a fixed order, sorted by label, bias every step.
:::

[The lowest 3.2% of a normal distribution average 2.2 standard deviations below its mean.]{.dgm-cap}
:::

2. minibatches of 64, dropping a partial last one?
3. minibatches of 100?

::: {.fragment .fade-up}
::: {.d2l-note}
**Answers.**

1. $\lceil 1000/64 \rceil = 16$: 15 full ones and one of 40.
2. 15; 40 examples sit out, a different 40 in each epoch.
3. 10, all full.
