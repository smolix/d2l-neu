**Idea:** An agent is a loop of observe, think and act whose success depends as much on the interface it is given and the context it keeps as on the model inside it.
**Opening:** On a repair task that needs five commands in a row, 10.1's model redoes a step it has already finished, because the output of that step scrolled out of a context it never managed. The concrete example is the opening cell: a 12-line scripted agent that applies the gold patch succeeds, and the live model over three seeds prints outcome, steps, summed prompt tokens and generated tokens, with the summed prompt tokens exceeding the final context length by a large factor. The open question: when the agent fails, is it the model's failure or the harness's?
**Teaches:**
- The loop: the model emits an action, the harness executes it in a sandbox and returns an observation, the episode ends on submit, a step limit, a context overflow or a format limit; `tab_lm_al_notation` maps the loop's objects to `tab_rl_notation` (prompt, agent turns, observations, trajectory, policy, reward as the hidden-test outcome).
- Code as the action space and the agent-computer interface: a bash-only interface, an interface with file viewing and editing commands (SWE-agent's ACI), and CodeAct (a Python program as the action); observations formatted to at most 2,000 characters (head and tail) with the exit code.
- Long horizons: token cost with and without prefix caching (the quadratic sum against the linear one), truncation, observation masking (keep the last k observations verbatim), compaction (ask the model for a summary at half the budget), file memory and subagents (described, exercised); interleaved thinking, a tool call inside the reasoning trace, as 9.6's bridge arrives here.
- Agent Skills: a `SKILL.md` folder with name and description loaded at startup, the full instructions loaded only when a task matches, bundled scripts loaded on execution; progressive disclosure as a context policy for procedural knowledge, with the token cost of each stage measured on the repair tasks.
- A failure taxonomy (`tab_lm_al_failures`: format, action loop, context overflow, navigation, edit failure, wrong fix, regression, tampering, no submit) with hand-labeling agreement on 30 failed episodes; cost and latency accounting per episode.
**Derivation:** Token cost over an episode of T steps with initial context c0, generated a_s and observed o_s tokens per step: without caching P equals T c0 plus the sum over s of (T minus s)(a_s plus o_s); with caching P equals c0 plus the sum of (a_s plus o_s); at constant u per step these are T c0 plus u T(T minus 1)/2 against c0 plus u(T minus 1). Smallest case: c0 800, 12 steps, 300 tokens each, giving 29,400 against 4,100. When compaction pays: replacing H history tokens by a summary of S tokens costing phi S saves tokens only for the remaining steps R above phi S/(H minus S) without caching, or (phi S plus c0 plus S)/(H minus S) with it; masking costs no generated tokens so its break-even is near zero. Check cells recompute the identity from logged lengths (exact for the full policy) and simulate the break-even for T 5 to 40 and phi in {1, 4} (within one step of the formula).

- The sandbox is accident-grade: each run is a fresh process with a replaced environment (no inherited `HF_TOKEN` or keys), resource limits (`RLIMIT_CPU`, `RLIMIT_AS` which is virtual size and not enforced on macOS, `RLIMIT_FSIZE`, `RLIMIT_NOFILE`, `RLIMIT_NPROC` which is per user), a wall timeout with a group kill, output capped at 20,000 bytes, a workdir watchdog; the isolation ladder is `bwrap` (network, PID and IPC unshared, read-only binds), then `unshare`, then limits only with a banner. Run the self-test on the actual host, never trust the design. Kernel exploits and side channels are out of scope (a gVisor container or a microVM is the adversary-grade answer).
- Stateless bash: `cd` and variables do not persist between commands; say so in the interface description. Small tasks hide context problems, which is why the budget is lowered on purpose; state it. A scaffold change can move success as much as a model change; always report the harness with the model. Hidden tests exist to catch overfitting to visible ones, and an agent that edits `tests/` must not pass.
- Summed prompt tokens depend on the caching convention; the cell flag states it. Qwen3's template drift breaks prefix caches silently; Qwen3.5 is prefix-stable (10.1), one reason the agent is Qwen3.5-4B.
