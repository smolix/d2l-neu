**Idea:** A grammar over characters becomes an automaton over tokens, and masking the logits with it guarantees a parseable string while changing the distribution in a way that can be computed exactly.
**Opening:** Some of 10.1's calls fail to parse: 100 unconstrained samples at temperature 0.7 from Qwen3-0.6B on the calculator prompt, with the parse-failure and schema-violation rates printed (a minority, not zero). The reader wants a decoder that cannot emit an invalid string. The open question: what does the guarantee cost, in time and in what the model would otherwise have said?
**Teaches:**
- A JSON schema as a regular language (required keys first, optional keys as groups, a whitespace policy of none, single or any) and the regular language as a byte-level automaton built by derivatives; a token is allowed in a state if its byte string reaches a live state, and the end-of-turn token exactly when the state is final.
- Tokens that span several transitions or end mid-string: the token automaton tracks one state per token through a trie walk; non-canonical tokenizations are allowed because the automaton constrains strings, not tokenizations; logits have 151,936 columns while the tokenizer has 151,669 ids, so the padding ids are always masked.
- Masking is not conditioning: token-by-token renormalization produces p(y)/prod Z(prefix), the true conditional is p(y)/p(L), the two agree only when the product of the normalizers is constant across the language; the KL between them has a closed form and a bound T log(1/(1 minus lambda)) over T constrained steps.
- Triggered grammars (free text until `<tool_call>`), masking before temperature and top-p, jump-forward decoding in one paragraph; "valid syntax is not a correct answer" and constraining after thinking (the grammar starts when the think block closes).
**Derivation:** The token automaton from the character automaton (acceptance is preserved; with all 256 single bytes in the vocabulary no live state becomes dead), and the distribution masked sampling produces. Smallest case: the language {ax, by} with p(a) 0.5, p(b) 0.4, p(other) 0.1, p(x given a) 0.01, p(y given b) 0.9. Then p(ax) is 0.005, p(by) 0.36, p(L) 0.365, the true conditionals 0.0137 and 0.9863; the normalizers are 0.9 at the first step and 0.01 or 0.9 at the second, so masked sampling gives 0.5556 and 0.4444, a ratio of 40.56 for ax and 0.45 for by, and a KL of 1.7028 nats. The exact fix weights each token by the probability of completing the language from that prefix, which is intractable in general. The case of vocabulary {a, ab} and language {ab} is the one-token illustration of a token spanning two transitions and appears first.

**Writer notes:**
- Mask before temperature and top-p, never after. Validity holds only at a final state: a generation cut by `max_new_tokens` is a valid prefix, not a valid output (check `is_final`). Bytes at or above 0x80 are admitted freely, so output can be invalid UTF-8 (the open exercise). Decoding a partial UTF-8 token does not give its bytes; work in bytes.
- `ws='any'` can emit whitespace forever; bound it. A schema whose property order differs from the model's habit forces low-probability tokens; a grammar that cannot express "do not call" makes the model hallucinate a call (the triggered arm exists for this reason).
- Reference implementation: XGrammar (`TokenizerInfo.from_huggingface(tokenizer, vocab_size=model.config.vocab_size)`, `GrammarCompiler`, `compile_regex`, `compile_json_schema(..., any_whitespace=False)`, `GrammarMatcher`, the bitmask functions; API as of 0.1 to 0.2, verify in the pinned release); Outlines (`outlines.from_transformers`); `llguidance` only if installed; vLLM `structured_outputs` for serving. Pin versions, smoke-test the first bitmask fill, and keep the `re` oracle if the production cells break. XGrammar supports rollback, which is what speculative verification needs (12.4).
- Performance fallbacks: if the pure-Python trie walk exceeds 1 s per state, precompute visited states only, restrict the headline to 10.1's tools, and cache masks to disk keyed by pattern and tokenizer revision; if 120 items exceed 10 minutes on CPU, cut to 20 per category or require `--gpu`; cap exact enumeration at 500 paths.
- Library additions: `d2l.parse_regex(pattern) -> Node` (literals, escapes, classes, groups, alternation, repetition, the `@{<tool_call>}` token for a special symbol); `d2l.schema_to_regex(schema, ws='single')`; `d2l.tool_call_regex(tools, fmt='qwen3', max_calls=3)`; `d2l.TokenFSM(pattern, tokenizer, vocab_size, trigger=None)` with `.start`, `.mask(state)`, `.step(state, token_id)`, `.is_final(state)`, `.n_states`, `.stats`; `d2l.constrained_generate(model, tokenizer, prompt_ids, fsm, max_new_tokens, temperature=0.0, top_p=1.0, seed=0)` (KV-cached, per-step log Z recorded); `d2l.enumerate_paths`, `d2l.exact_masked_distribution`. The XML format of Qwen3.5 is left to an exercise. Detail: blueprint ch10 §10.2.
