**Idea:** Decode time tracks the bytes read per token, so weight-only quantization speeds up decode, while quantizing activations as well is what speeds up prefill and large batches.
**Opening:** The reader has 7.5's four-bit model and the fact from `sec_hardware` that single-stream decode is bound by weight bytes over bandwidth. The opening cell loads Qwen3-1.7B in BF16, prints its measured decode tokens per second next to the bound computed from its byte count, then applies 7.5's four-bit round trip to every linear layer and prints perplexity (fine) and tokens per second (unchanged within noise), because the dequantized weights are stored in BF16 again. The question the section answers is what has to change for the smaller file to become a faster model, and the closing question is why eight-bit activations, which should help prefill, hurt accuracy in a way eight-bit weights do not.
**Teaches:**
- What changes from fine-tuning to inference: memory traffic and arithmetic rate instead of capacity, activations as well as weights, calibrated final weights judged on held-out quality and speed; one recap paragraph of 7.5's absmax, blockwise and NF4 quantizers with the table `tab_lm_q_vs_qlora`.
- Granularity and effective bits: per-tensor, per-channel, per-group scales for weights and per-token scales for activations; symmetric against asymmetric grids; range clipping; `b_eff = b + (b_s + b_z)/g`, with the formats of this chapter in `tab_lm_q_effbits` (INT4 at group 128 is 4.125 bits; GGUF Q4_0 is 4.5 and Q4_K is 4.5; MXFP4 is 4.25; NVFP4 is 4.5 plus one float per tensor).
- Weight-only against weight-and-activation quantization and the kernels that make each fast: dequantize inside the matrix multiply (tinygemm, Marlin) against an integer or FP8 matrix multiply with scaling in the epilogue; why a per-input-channel activation scale cannot be applied in an integer epilogue, which is the problem 11.2 solves.
- A roofline for one quantized layer: the batch at which a weight-only format stops helping, and why W8A8 is flat in the batch and helps prefill rather than small-batch decode.
- GGUF block formats as a two-level scheme (super-blocks with sub-scales), checked against the bytes of a real tensor, and why a `Q4_K_M` file mixes types.
- Bits against parameters at a fixed memory budget: at four gigabytes of weights, is Qwen3-1.7B in BF16, Qwen3-4B in INT8 or Qwen3-8B in INT4 the better model?
**Derivation:** Speed of a quantized linear layer. With weight bytes per parameter `w_f`, activation bytes `a_f` and peak rate `π_f` of the unit a format uses, `t_f(B) ≥ max((w_f mn + a_f B(m + n))/β, 2Bmn/π_f)`; weight-only formats gain up to `16/b_eff` at small batch and lose the gain by `B* = π w_f/(2β)`; W8A8 gains the integer-to-float rate ratio at every batch. Smallest case: one 2048 by 6144 layer of Qwen3-1.7B at `B = 1` and `B = 256` with `tab_gpu_specs` numbers, then the whole model: the tied head and embedding stay in 16 bits, so quantizing the blocks alone caps the decode speedup below the bytes ratio (the arithmetic of 12.1's byte accounting, previewed in one line).

**Writer notes:** The notebook's first lesson is that an accuracy simulation is not a speedup; keep the opening cell's "unchanged tokens per second" visible and do not tune it away. Measured bandwidth and rate ratio replace datasheet numbers in every overlay (the datasheet ridge is not exact). Decode must be timed with CUDA graphs; eager timing hides the byte ratio at batch 1 (`subsec_comp-overhead`). Blocks of `d2l.quantize_blockwise` run over the row-major flattened tensor, so a block size dividing `d_in` equals a group along the input dimension; assert `d_in % block_size == 0`. `torch._int_mm` has shape restrictions (a minimum row count and multiples of eight) to be verified against the pinned version; the decode path pads or falls back and the timing says which. FP8 W8A8 is skipped on A100 by design (no FP8 tensor cores; storage plus dequantization only). Quantizing the head and embedding hurts quality disproportionately and saves less than the body; the standard choice skips `lm_head` and the embedding, and the notebook says so once. The pre-quantized Hub checkpoints (`Qwen/Qwen3-1.7B-FP8`, `Qwen/Qwen3-1.7B-GPTQ-Int8`, `Qwen/Qwen3-8B-AWQ`, `Qwen/Qwen3-4B-AWQ`) are existence checks only, each wrapped in a try/except and marked `n/a` if the pinned package set cannot run it. Reference implementation and tolerance: the reference `fake_quant` round trip against torchao's dequantized weights (exact equality of codes, scales within float tolerance); `pack_int4` and `unpack_int4` exact. The GGUF byte counts (Q4_0 18 bytes per 32, Q8_0 34 per 32, Q4_K 144 per 256, Q6_K 210 per 256) are asserted against the `gguf` package table rather than typed into prose. Do not re-teach: formats (`sec_numerics`), the decode bound's derivation (`sec_hardware`), the quantizers (7.5). Library additions: the exports listed in the chapter notes, all `#@save`; the artifact `data/compression_report.jsonl`.
