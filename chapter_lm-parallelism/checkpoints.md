**Idea:** A checkpoint is a sharded copy of the training state whose write must hide behind training and whose layout must be loadable onto a different number of GPUs.
**Opening:** The reader saved a state dict in `sec_read_write` and learned the atomic rename and the resume-parity check of `subsec_training_long_run`. One concrete example: Qwen3-8B's checkpointed state is about 98 GB at 12 bytes per parameter; written synchronously to a shared file system at 2 GB/s it stalls training for 50 seconds, and at one save every half hour that is three percent of the run, before a single failure. The open question: how often to save, how to make a save cost almost nothing, and how to load the result onto four GPUs when it was written by eight.
**Teaches:**
- What a checkpoint holds: fp32 master parameters and the two Adam moments (12 bytes per parameter against 16 in memory), scheduler, RNG, EMA, loss-scaler and the data cursor (4.1's `d2l.PackedStream.state_dict()`), never gradients or activations; sharded saves where each rank writes its shard, replicas deduplicated, a metadata file with chunk offsets, an atomic commit marker.
- The cost of a save: synchronous, the stall is the write time S / (g beta_w) with the shared file system's aggregate bandwidth divided among ranks; asynchronous, the stall is the device-to-host staging copy S / (g beta_d2h) and the write proceeds in the background, with backpressure when the write outlasts the interval; pinned staging memory per rank; the measured slowdown while persisting.
- The interval: Young's square-root rule from the stall and the time between failures, Daly's correction, and the flatness of the optimum; the failure rate is a parameter here (6.10 measures it).
- Resharding: a tensor saved as chunks at offsets is loaded into any layout by reading the overlapping chunks; the data cursor as one global integer so that any world size replays the same sample multiset; validation before loading (commit marker, shard sizes, manifest checksums).
**Derivation:** The Young-Daly interval (blueprint ch06 6.8 D2). Checkpoint every tau seconds of compute at cost delta, restart cost R, exponential failures with mean M: the expected wall time for T_s seconds of work is (T_s / tau) M e^{R/M} (e^{(tau + delta)/M} - 1), whose minimizer satisfies e^{(tau + delta)/M}(1 - tau/M) = 1; to first order tau* = sqrt(2 delta M) (Young 1974), with Daly's higher-order terms for delta < 2M; the optimal waste before restarts is about sqrt(2 delta / M). Smallest numeric case: delta = 60 s and M = 8 h give tau* about 1,859 s by Young and 1,819 s exact (a 31-minute interval, waste about 6.5%); an asynchronous save with delta = 10 s gives tau* about 759 s and waste about 2.6%. The stall model delta_sync = S / (g beta_eff) and delta_async = S / (g beta_d2h) plus backpressure is stated and checked by measurement within 30% (I/O stacks are noisy; the cell prints the ratio).

**Writer notes:** Pitfalls (blueprint 6.8): an interval chosen by habit ("every 1,000 steps") rather than from delta and M, and the fact that halving delta helps only by 1/sqrt(2); counting the asynchronous save as free (staging blocks and persistence competes for bandwidth); a directory without an atomic commit, so a partial save is picked up as latest; a per-rank data cursor on resume with a different world size (duplicated or skipped samples); forgotten optimizer, scheduler, RNG, EMA and loss-scaler state; collective timeouts short enough to kill a run during a slow but legitimate save; the page cache making a save "finish" before it is durable (time `fsync`). API names at the pin: `save`, `load`, `async_save` returning `AsyncSaveResponse` with `staging_completion` and `upload_completion`, `FileSystemWriter`, `DefaultStager`, `Stateful`, `get_state_dict`, `set_state_dict`; drift is a risk (fallback: a thread-based writer of our own with the same stall measurement). Kill injection on SLURM can leave zombies; `launch` cleans the process group and the restart uses a fresh launch. Equality after resharding is non-bitwise; the band is three times the reference's spread.
