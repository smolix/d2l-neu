**Idea:** A job across machines is a set of processes that must agree on their ranks, their groups and the order of every collective, and when they disagree the job hangs rather than fails.
**Opening:** The reader launched `torchrun --standalone` sidecar scripts in `sec_multi_gpu_concise` and read `NCCL_DEBUG=INFO` in its exercise. One concrete example: the same script started with `--standalone` on each of two nodes runs two independent four-rank jobs that never find each other, and a one-line change to the collective order on one rank freezes all eight for the length of the timeout. The open question: what the ranks must agree on, how to launch them so they do, and how to read a frozen job's state when they did not.
**Teaches:**
- Rendezvous: `torchrun --nnodes --node_rank --rdzv_backend --rdzv_endpoint` per node, the SLURM `srun` and `sbatch` equivalents, and `d2l.launch(script, nodes, gpus_per_node, **env)` which submits a `%%writefile` script in `torchrun`, SLURM, `ssh` or loopback mode and collects per-rank logs into a bundle; rank, local rank, world size, node rank, and the process group's backend.
- Device meshes: `init_device_mesh` over named axes, contiguity (a group along an axis lies inside one node iff its stride times its size is at most the GPUs per node), the mesh as the object later sections shard over.
- Logs: rank-tagged JSON lines with wall and monotonic clocks, clock alignment across nodes from synchronization events, and the gathered hostnames as the first check that the job is what the launcher said.
- Hangs: collectives match by sequence number on a communicator, so swapped call sites combine the wrong tensors when shapes agree and hang or error otherwise; timeouts, `TORCH_NCCL_ASYNC_ERROR_HANDLING`, the flight recorder's dump of in-flight collectives per rank, and the reading of its output to name the rank and the call site; the `NCCL_DEBUG=INFO` header as the transport check (NVLink, shared memory, InfiniBand, sockets).
**Derivation:** Matching by sequence number (blueprint ch06 6.1 D1): on one communicator the i-th collective issued by each rank is matched with the i-th issued by every other rank regardless of call site, so the outcome is silent corruption iff the (op, count, dtype) sequences agree while the buffers' meanings differ, and a hang or an error otherwise. Smallest numeric case: two ranks, rank 0 issues all-reduce(A = 1) then all-reduce(B = 10) and rank 1 the reverse; both complete, and rank 0's "A" comes back as 11. Second statement, checked in a cell: a launch over N nodes each unhealthy with probability q succeeds with probability (1 - q)^N, and a job's time to first failure scales as 1 / (N r_node) (D2; 6.10 refits the rates).

**Writer notes:** Pitfalls (blueprint 6.1): `--standalone` on each node of a multi-node job is the opening symptom; "a hang is a slow network" is wrong until the flight recorder says otherwise; equal shapes hide order bugs; starting a launch from a kernel that already holds GPU memory; clock skew read as straggling; a shared file system that is not shared; `NCCL_DEBUG=INFO` left on in production; `ok=True` without checking world size and transport. Environment-variable names drift (`TORCH_NCCL_DEBUG_INFO_TEMP_FILE` against `TORCH_FR_DUMP_TEMP_FILE`), so `launch` keeps both behind a version check tested on the T2 pair. Zombie ranks after a failed launch poison the next run on shared nodes; `launch` kills the process group and checks GPU ownership, and the text says a cluster epilog is the real fix. The flight recorder is NCCL-only, so T1 replays committed dumps and the notebook states it. Do not re-teach DDP, bucketing, the ring, the alpha-beta model, or the scaling ladder (`sec_training_systems` and `fig_tools_training_ladder` are linked). Exports: `d2l.launch`, `d2l.LaunchResult` (`.logs(align=True)`, `.rank0_stdout()`, `.nccl_info()`, `.raise_for_status()`), `d2l.init_dist`, `d2l.rank_log`, `d2l.read_rank_logs`, `d2l.CommCounter` (wire-byte factors as in nccl-tests), `d2l.comm_events` (reads `record_param_comms` events of a profiler trace; the counter for library code), `d2l.parse_nccl_info`; artifacts `lm-launch-<tag>` (rank logs, NCCL header, flight-recorder dumps, the sbatch script, `meta.json`). Detail: blueprint ch06 6.1 (launch contract, bundle format, D1 to D3, pitfalls, risks). `launch` supports `ssh` mode in the first release (it is the fallback for clusters without SLURM); the DDP baseline here is the reference model, because the step must fit 20 GB at 16k tokens per GPU.
