# Pretraining
:label:`chap_lm_pretraining`

The reader has trained the GPT of :numref:`sec_gpt` for an afternoon on one GPU and read its loss curve. A real pretraining run lasts days, is interrupted and resumed, spikes at hour six, runs its matrix multiplications in eight bits, is continued on new data after it finishes, and is read almost entirely from its logs. This chapter builds the parts of that run that an afternoon never exercises, and trains the reference model that later chapters shard, fine-tune, quantize and serve.

**Writer notes:**
- *Running models and artifacts.* The chapter produces **the reference model**: a 138M-parameter decoder (138,442,752 parameters; 18 blocks, width 768, 12 query heads and 4 key-value heads of dimension 64, SwiGLU width 2,048, tied embeddings, RoPE base 10,000, QK-norm off, vocabulary 32,768) trained on 3.15B FineWeb-Edu tokens at context 4,096 with WSD (warmup 300 steps, stable to step 5,100, linear decay to zero at step 6,000; batch 524,288 tokens; AdamW (0.9, 0.95), weight decay 0.1, clip 1.0, z-loss 1e-4, peak learning rate 6e-4, bf16 with fp32 master weights). It is a one-off T3 job (about 1.3 to 1.7 h on 8x A100 40 GB at 35 to 45% MFU, assumed efficiency 0.9) whose outputs are uploaded once to a d2l-owned Hugging Face repository and pinned by commit hash in `DATA_HUB` (`01_interfaces.md` §3; never `main`): `lm-r2-config`, eleven bf16 checkpoints `lm-r2-s{500,1000,2000,3000,4000,4500,4800,5100,5400,5700,6000}` (276.9 MB each), the stable-phase branch point `lm-r2-s5100-state` (fp32 weights, AdamW moments, scheduler and stream state, RNG; 1.66 GB), `lm-r2-train-log`, `lm-r2-evals`, the T1 preset checkpoint and log `lm-r2t1-s1526`, `lm-r2t1-log` (25,173,376 parameters), and `lm-fwedu-val-domains`. The same job includes **the ladder**: three sizes below the reference model at two token budgets (see 4.2), with the WSD decay branched from each plateau so one run yields two finished points, committed as `lm-ladder-config`, `lm-ladder-logs` and `lm-ladder-evals`; 4.6 and assignment A5 fit it. The reduced T1 configuration everywhere is the `t1` preset (25.2M parameters, 100M tokens, about 4 to 6 minutes of compute on one 16 GB GPU). Consumers: Chapter 6 shards the reference model; 7.2 and 7.7 use it as the non-Qwen model; Chapter 11 quantizes it; 12.1 serves it; 14.1 reads its configuration. The tokenizer and the token shards are Chapter 3's (`d2l.r2_tokenizer`, `d2l.write_shards`, `d2l.TokenShards`, keys `lm-r2-tokenizer`, `lm-fwedu-val`, `lm-fwedu-shards-100m`, `lm-fwedu-manifest-4b`): byte-level BPE, vocabulary 32,768 (a multiple of 128, so no embedding padding), EOS id 0 appended per document, no BOS, 32 reserved special ids 0 to 31, shards as flat `uint16` `.bin` plus `uint32` `.idx` plus `meta.parquet` and `manifest.json` in the `d2l-corpus/1` format; ids above 65,535 (Qwen3's vocabulary in 4.4) force `uint32`.
