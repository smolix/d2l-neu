**Idea:** With a verifier the reward is exact, and the remaining choices are how to aggregate tokens into a gradient and how to keep the policy's entropy from collapsing.
**Opening:** An arithmetic problem has one checkable answer, so there is no reward model to fool. The checker must still find the answer inside a few hundred generated tokens, and a first cell samples eight answers per problem from the SFT checkpoint and counts the groups where all eight agree, which carry no signal. As the policy learns, its entropy falls and the groups agree more often. The open question is why sampling, not the update, sets the cost of every step, which 8.5 takes up.
**Teaches:**
- Robust verification: canonical answers (fractions, `\frac`, units, thousands separators), the last boxed answer only, empty or multiple answers score zero, a test table of at least 20 adversarial responses run before any training; the GSM8K false-negative rate measured on reference solutions.
- GRPO on multi-token responses with the token-level state $s_t = (x, y_{<t})$: group advantages, the sampling engine, minibatches, and the diagnostics panel (accuracy, mean length of correct and incorrect responses, entropy, clip fractions, fraction of zero-variance groups).
- The aggregation choices restated and their consequence measured: the divisor per sample, per token or a constant, and the standard-deviation normalization, change which responses dominate the gradient and how length drifts.
- New: overlong filtering (a soft penalty near the length cap), CISPO (clip the importance weight, not the token, and stop its gradient), entropy collapse and its first-order cause, and the predictable, sigmoid-shaped scaling of accuracy with RL compute.
**Derivation:** The first-order entropy change under one policy step. For a softmax policy with logits $z$ and an update $\delta z$, $\delta H = -\textrm{Cov}_{a \sim \pi}(\log \pi(a), \delta z_a)$; a natural-gradient step $\delta z = \eta A$ gives $\delta H = -\eta \,\textrm{Cov}(\log \pi, A)$, so entropy falls fastest when high-probability tokens receive positive advantage. Smallest case: a 6-way softmax with $\pi = (0.5, 0.2, 0.1, 0.1, 0.05, 0.05)$ and advantages $(+1, 0, 0, 0, -1, 0)$ at $\eta = 10^{-4}$, where the formula and the recomputed entropy agree to relative `1e-3`. A second small case, in the exercises, is the standard-deviation weight $w_K(p) = \mathbb{E}[\hat\sigma_K] / (p(1 - p))$ for binary rewards: at $K = 8$ it is 2.33, 1.96 and 1.86 at $p = 0.1, 0.3, 0.5$, so normalization up-weights easy and hard prompts.

**Writer notes:**
- `torch.std` is unbiased by default; the chapter uses the population standard deviation (they differ by $\sqrt{K/(K-1)}$), and the autograder fixture makes the choice observable. The group mean shrinks the gradient by $(K - 1)/K$; leave-one-out removes it.
- A verifier bug is an optimization target: run the test table first; the rows include `\boxed{12.0}`, `\boxed{\frac{24}{2}}`, `1,000`, two boxed values, a hedge `\boxed{12 or 13}`, a unicode minus, text after the box, a boxed value quoted inside the reasoning, and truncation before the box. Format rewards are off by default.
- Discarding zero-variance groups (DAPO's dynamic sampling) changes the prompt distribution; say so when it is on. Calibrate the task profile so the initial pass rate sits between 0.2 and 0.6, else most groups carry no signal (fallback: filter prompts by a 16-sample probe).
