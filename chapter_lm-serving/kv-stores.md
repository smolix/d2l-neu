**Idea:** A cache that outlives one GPU's memory becomes a store across tiers and replicas, and once it does, where a request is routed decides whether its prefix is near.
**Opening:** The reader has 13.4's prefix cache, whose hit rate falls as the GPU pool fills, and 13.5's swap, which moves blocks to host memory and back. The opening cell prints, for the Mooncake agent excerpt, the hit rate with a 2 GiB GPU pool, with 8 GiB, and with a 2 GiB pool backed by 8 GiB of host memory, next to the measured time to reload a 1,024-token prefix from host memory and the time to recompute it. The question is when reloading beats recomputing and how far a cache can be from the GPU, and the closing question is what happens when there are four replicas and a prefix is on only one of them.
**Teaches:**
- The tiers a cache can live in (GPU, pinned host memory, local NVMe, a remote store over the network) with their bandwidths and latencies restated from the hardware chapter; reload against recompute as the only question that matters; layer-wise pipelining that hides a transfer behind a prefill.
- A two-tier prefix cache: GPU blocks plus host blocks under one radix tree, with promotion on hit and demotion on eviction; the hit rate of two tiers from Che's approximation applied to the combined capacity; the expected time to first token as a mixture of GPU hits, host hits and misses.
- Compressing the cache for transfer (CacheGen: delta coding of keys and values with a quality-aware bit rate) and reusing non-prefix chunks with partial recompute (CacheBlend) as the two one-difference relatives.
- Replicas: with `R` independent caches and random routing each replica sees a thinned stream, so the hit rate equals one cache at rate `λ/R`; prefix-aware routing (hash the first page, or query a global index of cached blocks) restores the single-cache hit rate at the price of load imbalance; the trade-off, and the router that mixes locality and load (the SGLang router's cache-aware policy, Dynamo's KV-aware router, Preble).
- A global store (Mooncake Store, LMCache) that decouples placement from routing: any replica can fetch a prefix over the network, so the router balances load and the store serves locality, at the transfer cost of the first paragraph.
**Derivation:** Reload against recompute, and the two-tier hit rate. Reloading `n` tokens costs `α + n k_KV/β_link`, recomputing costs `n · 2N/P_eff`, so to first order reloading wins above `β* = k_KV P_eff/(2N)`, independent of `n`; for Qwen3-0.6B `β*` is about 10 GB/s (a PCIe host link wins, a 10 Gb/s network loses), for Qwen3-30B-A3B about 3 GB/s. The two-tier hit rate is `H(C_gpu)` on the GPU and `H(C_gpu + C_host) − H(C_gpu)` on the host, with `H` from Che's approximation (13.4), and the expected time to first token is the mixture. Smallest case: a Zipf(1) set of 64 prompts, 8 GPU and 32 host slots. Thinning: with `R` replicas and random routing, each replica's hit rate is `H` evaluated at rates `λ_i/R`, which is lower for every capacity.
