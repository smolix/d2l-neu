**Idea:** Fixed-size blocks located through a per-sequence table waste at most one block per sequence and never fragment, so the number of concurrent requests is bounded by the tokens they hold rather than the tokens they might hold.
**Opening:** The reader runs 13.2's engine with a fixed 8 GiB pool at a load above the slot store's saturation. The opening cell prints the number of slots (29 at 2,560 tokens each), the mean live length, the fraction of reserved cache that holds tokens, and the throughput: most of the reserved cache is empty and the batch is capped by slots. The question is how to reserve only what a sequence has, and the closing question is what two sequences that start the same way should share.
**Teaches:**
- Three kinds of waste in contiguous allocation (internal, external, duplication) shown by an allocator simulation with a reservation policy, an oracle that knows final lengths, and paging; even perfect length knowledge fragments.
- Blocks and block tables: logical blocks of a sequence map to physical blocks through a table (`physical = table[pos // B]`, `offset = pos % B`); one pool tensor per layer; allocation on demand as tokens arrive; the allocator's state is a free list and a reference count.
- The allocator's invariants (a block is free or referenced, never both; references equal table entries; table lengths equal `⌈ℓ/B⌉`; a shared block is never written; freeing everything returns every block) and a randomized operation generator that checks them.
- The paged read: the block-table variant of 12.2's decode kernel against a gather-then-attention reference; the cost of the indirection; vAttention's alternative (virtual memory keeps the cache contiguous so an ordinary kernel works) as the one-difference relative.
- Block size as a design variable (waste grows with `B`, bookkeeping and gather overhead shrink, prefix-cache granularity coarsens); copy-on-write forks for parallel sampling and beam search; recurrent state of hybrid models (constant size per snapshot, so a prefix is cacheable only at saved boundaries) in one paragraph with a config-based table.
**Derivation:** Expected waste and the concurrency gain. With residues of `ℓ mod B` uniform, the waste per sequence has mean `(B − 1)/2` and variance `(B² − 1)/12`; reserving `L_max` instead wastes `L_max − ℓ`, so a fixed pool holds `G(B) = L_max/(ℓ̄ + (B − 1)/2)` times more sequences; block-table overhead is 4 bytes per block. After a fork of `n` samples from a prompt of `P = qB + r` tokens generating `T` each, copy-on-write uses `⌊P/B⌋ + n⌈(T + r)/B⌉` blocks and `n − 1` partial copies. Smallest case: 64 requests, maximum 4,096, mean 500, block 16: `G = 8.1`; a 70-token prompt, three samples of 20 tokens, `B = 16`: 10 blocks with copy-on-write against 18 without.

**Writer notes:** Paging does not shrink the cache; it removes waste around it (12.6 and 14.3 shrink the values). A block shared by two sequences is never written in place; the bug shows up only when two sequences diverge inside a shared block (test with a partial last block). `copy_slot` on a paged store swaps two tables and moves no bytes, which is what `FastGenerator.free`'s compaction costs here. The reference gather copies the cache per layer and can dominate step time at long contexts; report gather time separately and use 12.2's kernel as the fast path.
